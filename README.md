# An Empirical Study on the Impact of Post-Training Quantization on Code Language Models

This repository contains the replication package for our empirical study evaluating the impact of six post-training quantization (PTQ) techniques on code language models. We assess both **functional correctness** (Pass@1) and **code quality** (SonarCloud metrics) across two models, three benchmarks, and two programming languages.

## Study Overview

We investigate how 4-bit PTQ affects code generation by comparing quantized variants against full-precision (FP16) baselines.

**Models:**
- CodeLlama-7B-Instruct
- Qwen2.5-Coder-7B-Instruct

**PTQ Techniques:**
- GPTQ
- AWQ
- GGUF (Q4_K_M)
- BitsAndBytes (NF4)
- AQLM (2×15, 4-bit)
- QuIP# (4-bit)

**Benchmarks:**
- [McEval](https://github.com/Leolty/mceval) (Java & Python)
- [CoderEval](https://github.com/CoderEval/CoderEval) (Java & Python)
- [BigCodeBench](https://github.com/bigcode-project/bigcodebench) (Python only)

**Code Quality Metrics** (via SonarCloud):
- Lines of Code (LoC)
- Cyclomatic Complexity (CyC)
- Cognitive Complexity (CoC)
- Maintainability (Code Smells)
- Reliability (Bugs)
- Security Hotspots

## Research Questions

- **RQ1:** How does PTQ affect the functional correctness of code generated by quantized code LLMs?
- **RQ2:** How does PTQ affect the non-functional (code quality) properties of generated code?
- **RQ3:** Is the impact of quantization sensitive to the complexity of the coding task?

## Statistical Tests

We use paired statistical tests to compare FP baselines against each quantized variant:

- **McNemar's test** for Pass@1 (binary pass/fail per task), with odds ratio computed as (b + 0.5) / (c + 0.5) where b = FP-pass-only and c = quant-pass-only discordant pairs
- **Wilcoxon signed-rank test** for SonarCloud code quality metrics (paired per task), with Cliff's delta as effect size measure
- **Holm-Bonferroni correction** applied within each benchmark × model group to control family-wise error rate

## How to Reproduce

### 1. Organize benchmark results
```bash
bash scripts/copy_results.sh --dry-run   # Preview
bash scripts/copy_results.sh             # Execute
```

### 2. Extract code for SonarCloud
```bash
python scripts/extract_py_for_sonarqube.py        # McEval Python
python scripts/extract_java_for_sonarqube.py       # McEval Java
python scripts/extract_codereval_for_sonarqube.py  # CoderEval (both languages)
python scripts/extract_bcb_for_sonarqube.py        # BigCodeBench Python
python scripts/fix_java_class_wrapper.py           # Wrap CoderEval Java in classes
```

### 3. Prepare pass@1 data
```bash
python scripts/prepare_pass1_java.py
python scripts/prepare_pass1_python.py
```

### 4. Collect SonarCloud metrics
```bash
python scripts/collect_sonarcloud_python.py --output-dir Analysis-and-Reports/Python
python scripts/collect_sonarcloud_java.py --output-dir Analysis-and-Reports/Java
```

### 5. Run statistical tests
```bash
Rscript statistical-tests/wilcoxon_java.R
Rscript statistical-tests/wilcoxon_python.R
Rscript statistical-tests/mcnemar_java.R
Rscript statistical-tests/mcnemar_python.R
```

### 6. RQ3 complexity analysis
```bash
python RQ3/rq3_prepare.py --entropy_csv entropy_buckets.csv \
                           --config RQ3/rq3_config_python.json \
                           --output_dir RQ3/results
```

- Python 3.9+ with `pandas`, `requests`
